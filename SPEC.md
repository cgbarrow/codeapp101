## 1. Objective

**What:** A fast, minimal personal todo app hosted as a Power Apps code app, storing data in Dataverse, usable on phone, tablet and desktop.

**Who:** An individual Microsoft 365 user with a Power Apps Premium licence who wants a distraction-free daily task list inside their tenant, not a third-party SaaS.

**Why:** Existing options are either heavy (Planner, model-driven apps) or outside the tenant's governance (Todoist, Things). This app is the "text field and a checkmark" experience, with tenant auth, DLP and data residency for free.

**Success looks like:** Opening the app and capturing a task takes under five seconds. The "Today" view shows only what matters today. Checking a box feels instant everywhere.

### User stories and acceptance criteria

**S1 · Fast capture (Core)**
- As a user I press `n` (or click "+") anywhere in the app, type, press Enter, and the task exists.
- Acceptance:
  - Quick-add input is focused within 100 ms of shortcut; Enter saves; Esc cancels.
  - Task appears in the list optimistically before the Dataverse round-trip completes; rolls back with an inline error toast if the create fails.
  - Typing `Buy milk on Friday` sets due date to the next Friday and strips the phrase from the title (title = `Buy milk`). Also handles `tomorrow`, `next week`, `in 3 days`, `at 3pm`, explicit dates (`Sep 30`, `30/9`), `every day|week|month`.
  - A preview chip shows the parsed date before saving; clicking it clears the parse.
  - The new task lands in the currently open list (or "Inbox" from the Today view).

**S2 · Cross-platform sync (Core)**
- As a user I check a task on my phone and see it checked on my laptop.
- Acceptance:
  - Dataverse is the only store. No local-only persistence except an optimistic in-flight cache.
  - Data refetches on window focus, on visibility change, and every 60 s while visible.
  - Layout works at 320, 375, 414, 768, 1024, 1440 px with no horizontal scroll.
  - Concurrency: last write wins on a field; completed state uses `PATCH` with only the changed columns.

**S3 · Due dates and reminders (Core)**
- As a user I set a due date and an optional reminder time and get alerted.
- Acceptance:
  - Task detail exposes date picker, optional time, and reminder offset (at time, 10 min, 1 h, 1 day before).
  - Overdue tasks are visually distinct and sorted first.
  - While the app is open and permission is granted, a browser notification fires at reminder time (checked every 30 s against locally cached reminders).
  - Out-of-app delivery via Power Automate is **Phase 2** (see Q3).

**S4 · Clean interface (Core)**
- As a user I see my tasks and nothing else.
- Acceptance:
  - Two levels of navigation only: list sidebar (collapses to a sheet on mobile) and task list. Task detail is an inline expand, not a new page.
  - Checkmark has a 200 ms completion animation and a 3 s "Undo" affordance; completed tasks slide to a collapsed "Completed" section.
  - Hallmark pre-emit critique stamp present with every axis ≥ 3; slop-test gates pass (no italic headers, no invented metrics, tokens only, mobile floors).
  - Keyboard: `n` new, `j/k` move, `x` toggle complete, `e` edit, `⌫` delete (with undo), `1..9` switch list, `t` Today.

**S5 · Multiple lists (Core)**
- As a user I group tasks in lists like Work, Personal, Groceries.
- Acceptance:
  - Create, rename, reorder (drag on desktop, up/down on mobile), archive lists. "Inbox" is created automatically on first run and cannot be deleted.
  - Deleting a list with tasks asks whether to move them to Inbox or delete them.
  - Each list shows an open-task count.

**S6 · Recurring tasks (Extra)**
- As a user I mark a task daily/weekly/monthly and it comes back after I complete it.
- Acceptance:
  - Recurrence choices: None, Daily, Weekly (same weekday), Monthly (same day-of-month, clamped to month end).
  - Completing a recurring task marks the current instance complete and creates the next instance in the same list with the next due date, copying subtasks in an unchecked state.
  - "Stop repeating" on a task ends the chain without touching history.

**S7 · Subtasks (Extra)**
- As a user I break a task into steps.
- Acceptance:
  - Up to 50 subtasks per task, each with title and done flag; reorderable.
  - Task row shows `2/5` progress; completing all subtasks does **not** auto-complete the parent (explicit tap only).

**S8 · Today view (Extra)**
- As a user I open the app and see only today's work.
- Acceptance:
  - Today = tasks due today or overdue, across all lists, grouped Overdue → Today, then by list.
  - Today is the default landing view; the app remembers the last view in `localStorage`.
  - Empty state copy: "Nothing due today." with a quick-add prompt. No confetti.

### Out of scope (v1)
Sharing/assignment, attachments, comments, tags/priorities, Teams tab embedding, offline mode, Power Apps mobile player packaging, multi-language.

### Dataverse schema (solution `CodeApp101`, publisher prefix `cb`)

Source of truth: `solution/generate.py` → `solution/src/customizations.xml`. Lookups are defined as one-to-many relationships (Dataverse creates the lookup column from the relationship).

**`cb_todolist`** (user-owned)
| Column | Type | Notes |
|---|---|---|
| `cb_todolistid` | PK | |
| `cb_name` | Text(100) | primary name |
| `cb_sortorder` | Whole number | |
| `cb_isinbox` | Yes/No | exactly one per user; app enforces |
| `cb_isarchived` | Yes/No | |
| `ownerid` | system | user-owned |

**`cb_todotask`** (user-owned)
| Column | Type | Notes |
|---|---|---|
| `cb_todotaskid` | PK | |
| `cb_title` | Text(400) | primary name |
| `cb_notes` | Multiline text | |
| `cb_list` | Lookup → `cb_todolist` | required; relationship `cb_todolist_cb_todotask_list`, cascade delete |
| `cb_duedate` | DateTime (User local) | nullable |
| `cb_hastime` | Yes/No | false ⇒ treat as date-only |
| `cb_reminderat` | DateTime | nullable |
| `cb_iscompleted` | Yes/No | |
| `cb_completedon` | DateTime | |
| `cb_recurrence` | Choice: 100000000 None, 100000001 Daily, 100000002 Weekly, 100000003 Monthly | values use the publisher option-value prefix; the app maps them to a `Recurrence` union type |
| `cb_recurrenceparent` | Lookup → `cb_todotask` (self) | links instances; relationship `cb_todotask_cb_todotask_recurrenceparent`, remove-link on delete |
| `cb_sortorder` | Whole number | manual order within list |

**`cb_todosubtask`** (user-owned)
| Column | Type | Notes |
|---|---|---|
| `cb_todosubtaskid` | PK | |
| `cb_title` | Text(400) | primary name |
| `cb_task` | Lookup → `cb_todotask` | required; relationship `cb_todotask_cb_todosubtask_task`, cascade delete |
| `cb_isdone` | Yes/No | |
| `cb_sortorder` | Whole number | |

Security role `Todo User`: Create/Read/Write/Delete at **User** level on all three tables; Read on nothing else.

Known SDK constraints to design around: lookups are set via `@odata.bind` on create/associate; no FetchXML; no alternate keys; always pass `select`.

## 3. Commands

One-time machine setup:
```bash
npm install --global @microsoft/power-apps-cli
pa auth login
```

Project bootstrap (first time only):
```bash
npx degit github:microsoft/PowerAppsCodeApps/templates/vite .
npm install
pa app init --display-name "Simple Todo" --environment-id Default-dc087386-56cb-4425-82f3-4b2dd04d62d8

pa app add data-source --connector dataverse --table cb_todotask
pa app add data-source --connector dataverse --table cb_todosubtask
```

Daily development:
```bash
npm run dev            # vite --mode mock: loads .env.mock (VITE_USE_MOCKS=true), in-memory sample data
npm run dev:dataverse  # vite on :3000 against real Dataverse; the Power Apps plugin prints the Local Play URL
npm run dev:smoke      # as dev:dataverse, with the development-only Dataverse smoke-test panel
pa app run             # Power Apps local host; open the "Local Play" URL in the tenant browser profile
npm run typecheck      # tsc -b --noEmit
npm run lint           # eslint . --max-warnings 0
npm run lint:fix       # eslint . --fix
npm run format         # prettier --write .
npm test               # vitest run
npm run test:watch     # vitest
npm run test:coverage  # vitest run --coverage
npm run e2e            # playwright test (mocked data layer)
npm run build          # tsc -b && vite build
npm run preview        # vite preview
```

Schema refresh after changing a table in Dataverse:
```bash
pa app refresh data-source --name todotasks   # data source names are in power.config.json
```

Publish:
```bash
npm run build
pa app push --solution-id <CODEAPP101_SOLUTION_ID>
pa app share --principal user@tenant.com --access play
```

Schema package (schema in Git):
```bash
python3 solution/generate.py     # regenerates solution/src/*.xml and solution/CodeApp101_1_0_0_0.zip
```
Import the zip via make.powerapps.com → Solutions → Import solution, then assign the `Todo User` role. Full steps and manual fallback: `docs/dataverse-setup.md`. Import before `pa app add data-source`.

## 5. Code style

```tsx
// src/components/TaskRow/TaskRow.tsx
import { memo } from "react";
import { useToggleTask } from "@/data/queries";
import { Checkmark } from "@/components/Checkmark/Checkmark";
import type { Task } from "@/data/repo";
import styles from "./TaskRow.module.css";

type TaskRowProps = {
  task: Task;
  isSelected: boolean;
  onSelect: (taskId: string) => void;
};

export const TaskRow = memo(function TaskRow({ task, isSelected, onSelect }: TaskRowProps) {
  const toggle = useToggleTask();
  const overdue = !task.isCompleted && task.dueDate !== null && task.dueDate < startOfToday();

  return (
    <li
      className={styles.row}
      data-selected={isSelected || undefined}
      data-overdue={overdue || undefined}
    >
      <Checkmark
        checked={task.isCompleted}
        label={`Complete ${task.title}`}
        onChange={() => toggle.mutate({ id: task.id, isCompleted: !task.isCompleted })}
      />
      <button type="button" className={styles.title} onClick={() => onSelect(task.id)}>
        {task.title}
      </button>
      {task.dueDate && <DueChip date={task.dueDate} hasTime={task.hasTime} />}
    </li>
  );
});
```

```css
/* src/components/TaskRow/TaskRow.module.css */
.row {
  display: grid;
  grid-template-columns: auto minmax(0, 1fr) auto;
  gap: var(--space-3);
  padding-block: var(--space-2);
  color: var(--color-ink);
  transition: background var(--motion-fast) var(--ease-out);
}
.row[data-overdue] .title { color: var(--color-danger); }
.row:hover, .row.is-hover { background: var(--color-paper-2); }
```

Conventions:
- **Files:** `PascalCase.tsx` for components, `camelCase.ts` for modules, one component per folder with its CSS module and test beside it.
- **Types over interfaces** for props and data shapes; `interface` only for the repo contracts in `data/repo.ts`.
- **Domain types are app-shaped** (`Task`, `List`, `Subtask` with `camelCase`, `Date | null`). Mapping to/from Dataverse `cb_*` columns happens only in `src/data/dataverse/`. Nothing outside `src/data` imports from `src/generated`.
- **No default exports** except route components required by the router.
- **State via attributes:** `data-selected`, `data-overdue`, `aria-*`; no boolean class-name soup.
- **Colours and fonts only via `var(--token)`.** Hallmark gate 48: an inline hex or `font-family: "X"` outside `tokens.css` fails review.
- **Every interactive component ships all 8 states:** default, hover, focus-visible, active, disabled, loading, error, success.
- **Errors surface to the user** through the Toast queue with an action where recovery exists (Retry / Undo). Never `console.error` alone.
- **Async data:** react-query hooks only; no `useEffect` + `useState` fetching.
- **Prettier:** 2-space, double quotes, semicolons, 100 cols, trailing commas.

| Level | Tool | Lives in | Covers |

Rules:
- Coverage gate: **90 % lines on `src/features` and `src/data`**, 70 % overall. CI fails below.
- Bug fixes use Prove-It: failing test first, then fix.
- `src/generated/**` excluded from coverage and lint.
- Tests must not hit Dataverse. The mock repo is the same one used by `npm run dev` with mocks on.

## 7. Boundaries

**Always**
- Run `npm run lint && npm run typecheck && npm test` before every commit; `npm run build` before every push.
- Keep Hallmark discipline: tokens only, pre-emit critique stamp, mobile verification at 320/375/414/768, no italic headers, no invented copy.
- Go through `src/data/repo.ts` for all persistence; keep `src/generated` untouched.
- Send only changed columns on update; always pass `select` on reads.
- Write an ADR in `docs/adr/` for any architectural choice (CLI, state library, schema shape, notification approach).
- Commit `power.config.json`; keep environment IDs and solution IDs there or in `.env.example`, never real tokens.
- Keep the spec current: schema or scope change ⇒ edit SPEC.md in the same PR.

**Ask first**
- Any change to the Dataverse schema (new column, type change, rename) or security role.
- Adding a runtime dependency beyond the stack table above.
- Changing CI/deploy workflows or the target environment.
- Adding a Power Automate flow or any connector other than Dataverse.
- Running `pa app push` to the environment.
- Deleting or archiving lists/tasks in bulk (data migration scripts).

**Never**
- Commit secrets, tokens, `.env`, or the `pa` auth cache.
- Hand-edit `src/generated/**` or `power.config.json` fields you didn't set via `pa`.
- Store task data anywhere other than Dataverse (no IndexedDB "cache" that outlives the session).
- Introduce a component library or inline colour/font values.
- Remove or skip a failing test to make CI green.
- Force-push `main`.

## 8. Success criteria (definition of done for v1)

1. `pa app push` succeeds and the app opens from make.powerapps.com for a second user in the tenant with only the `Todo User` role.
2. Capture: from app focus, `n` → type → Enter creates a visible task in ≤ 5 s wall-clock, and `Buy milk on Friday` yields title `Buy milk`, due next Friday.
3. Sync: a task completed on a phone browser shows completed on a desktop tab within 60 s without reload, and immediately on focus.
4. Today view lists only overdue + due-today tasks across all lists and is the default landing.
5. Completing a weekly recurring task creates the next instance dated +7 days with subtasks reset.
6. Reminder: with browser permission granted and the tab open, a notification fires within 30 s of the reminder time.
7. Lighthouse (mobile, throttled) on the built app: Performance ≥ 90, Accessibility ≥ 95; no horizontal scroll at 320 px.
8. CI green: lint 0 warnings, typecheck clean, unit + component + e2e passing, coverage gates met.
9. Hallmark audit of the final UI returns no gate failures.
10. README lets a new developer go from clone to Local Play in under 15 minutes.
