Reproduce:

```bash

npx lighthouse http://localhost:4173/ --output=html --output-path=docs/design/lighthouse.html
```

The build is the mock-data build, because the Dataverse build cannot run outside the Power Apps
host. The two differ only in which repository implementation `createRepos` returns; both bundle the
same UI.

**Layout shift, found and fixed.** The first run scored CLS 0.152. The Today view was the cause: its
quick-add box only rendered once the Inbox query resolved, and its loading placeholders sat in a
different slot from the content that replaced them, so the page jumped twice while loading. The slot
now reserves its height and the placeholders render where the tasks will be. CLS is 0 on repeat
runs.

SEO's remaining point is a missing `robots.txt`, and the agentic-browsing category wants an
`llms.txt`. Neither applies to an app that is served from inside the Power Apps host, behind a
sign-in, and never crawled.

**0 critical · 0 major · 2 minor**, both fixed in the same task:

| Severity | Tell | Where | Fix |

Checks that passed: the structural fingerprint is an app shell, not the centred-hero template, and
the stamp matches what shipped; no colour or `font-family` value outside `tokens.css`, enforced by
`src/styles/tokens.node.test.ts`; no italic headings; `overflow-x: clip` on `html, body` and no
horizontal scroll at 320, 375, 414, 768, 1024 or 1440 px (`e2e/shell.spec.ts`); every grid track that
can hold long text uses `minmax(0, 1fr)`; headings wrap with `overflow-wrap: anywhere`; motion uses
the token easings, animates only `transform` and `opacity`, and collapses under
`prefers-reduced-motion`; every interactive component documents and ships all eight states. The
Checkmark's success state is the checked tick, and the skeleton placeholders are not interactive;
both say so in their stamps.
